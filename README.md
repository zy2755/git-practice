**做了什么：** 原来只显示城市名（「连云港」），现在拼成「市 + 县/区」连写，跟 QQ 一样：

| 接口给的两级 | 拼出来的名字 |
| --- | --- |
| 连云港市 + 灌南縣 | **连云港灌南** |
| 濟南市 + 章丘区 | **济南章丘** |
| 北京市 + 東城區 | **北京东城** |

| 阜新市 + 阜新蒙古族自治縣 | **阜新蒙古族自治县**（县名已含市名，不再重复前缀） |
| 只有一级（南京市 / 空） | **南京** |

具体改动（只动 `index.html`）：

1. 定位那边**同时收下 `city` 和 `locality` 两个字段**（原来只要一个 `city`），
   交给新函数 `composeCityName()` 拼装；备用链路 `geojs.io` 同理。

   但「自治县/自治州/自治旗/自治区」**整名保留**——削掉会变成「阜新蒙古族」，不通顺。
3. 繁简表补了一批地名高频字（`黃`→黄、`灘`→滩、`嶺`→岭……），共 92 条，无重复键、无自我映射。
4. 拼装的三条去重规则：两级一样只留一个；县名里已含市名就不再前缀；否则直接连写。

**顺手修的窄屏问题（真 bug）：** 名字变长后在手机上炸了 —— `#weather` 是 `width: fit-content`，
内容一长就**一路撑到整屏宽、左右贴着屏幕边**（连「连云港灌南」都折成两行、胶囊变成通栏）。

- `max-width: calc(100% - 2 * var(--page-pad-x))` —— 最多只到页面内容的宽度，左右总留白；
- `#weather > span { white-space: nowrap }` —— 每一段（「多云 26°C」）不拆开，要换行在「·」处换；
- 手机媒体查询里更紧凑（字号 `0.85rem`、分隔点 `0.2em`、`letter-spacing: 0`）。
  实测 375px 宽下：「连云港灌南 · 多云 26°C · 21~27°C · 体感 29°C」**单行 327px 放得下**。

**验证：**

### 2026-09-27 14:45 — 天气：换掉限流的接口 + 缓存改成"会自动纠正"

起因：和田反馈两件事 —— ① 线上还是 9 月 25 日那版，没刷新；② 电脑上打开本地文件，
天气仍显示「东京都」（手机上是「南京」，是对的）。

**先说结论：②不是代码错，是两层缓存叠在一起。** 分别是页面自己的 localStorage 缓存、
和 CDN 缓存；而「东京都」这个错误结果本身，是**代理还开着的时候**测出来的（代理一关，
浏览器立刻能拿到南京）。这次把两层都治了。

- **改动一：接口换血（原来的会限流 + 备用是坏的）**
  排查时在浏览器控制台抓到两条硬证据：
  - `ipwho.is` 返回 **HTTP 429（请求过多）**，而且 **429 的响应体里没有经纬度**——
    这就是之前一直没想通的"偶发返回 success 但字段是空的"的真相：不是抖动，是**限流**。
  - 我原先设的备用 `ipapi.co` **根本没有 `Access-Control-Allow-Origin`**，
    浏览器直接以 CORS 报错拦掉（`has been blocked by CORS policy`）——等于**备用形同虚设**，
    主接口一限流就彻底没人顶上。
  现在改成**两步、两个请求**：
  | 步骤 | 接口 | 说明 |
  |---|---|---|
  | ① 定位 + 中文地名 | `api.bigdatacloud.net/data/reverse-geocode-client?localityLanguage=zh` | **不带坐标时它自动按访问者 IP 判断**，一次返回中文城市名 + 经纬度，等于把原来的"拿坐标 + 译中文名"合成一步 |
  | ① 备用 | `get.geojs.io/v1/ip/geo.json` | 只保证给经纬度（城市名可能为空，页面本就支持不显示地名） |
  | ② 天气 | `api.open-meteo.com/v1/forecast` | 经纬度 → 实时天气 |
  两家都实测过 `access-control-allow-origin: *`。请求数从 3 降到 2，少打一个接口。
- **改动二：缓存策略改成"先贴旧的、同时拉新的"（stale-while-revalidate）**
  原来写的是"30 分钟内直接吃缓存、不发请求"——**省事但会害人**：一旦缓存里存的是错的城市，
  它会一直显示那个错的，直到过期，用户完全没法自救。
  现在改成：
  - 2 分钟内的缓存 → 直接用，不再请求（避免手抖连点刷新时反复打接口）；
  - 超过 2 分钟 → 先把缓存贴上去让页面立刻有内容，**同时照样去拉最新**，拉回来直接覆盖。
  ⇒ 效果：**就算缓存里是「东京都」，页面几秒后会自动改成真实城市**，不用用户清缓存。
- 验证（无头 Edge + CDP，实测）：
  - 首次打开 → `🌦 连云港·毛毛雨 26°C · 21~26°C · 体感 29°C`，无控制台报错；
  - **自愈专项测试**：先正常打开，再往 localStorage 塞一条 10 分钟前的假缓存（城市="东京都"），
    重新加载 → ① 立刻显示「东京都」垫底 ✔ ② 几秒后**自动变成「连云港」** ✔
    ⇒ 这条专治和田遇到的"旧缓存赖着不走"；
  - 四套皮肤重跑一遍，配色仍全部跟随，`visible:true`。
- ⚠️ **CDN 缓存这件事另说**（跟上面的代码无关）：线上首页 `/` 被网关压着一个 **9-25 的旧副本**
  （`Eo-Cache-Status: HIT`、`Age` 一路涨到 1700+ 秒），而 **`/index.html` 是新的**（MISS + 今天日期）。
  根因很可能是：**上次发布的那一瞬间，我恰好用 `curl` 请求了根地址 `/`，
  把当时还是旧内容的响应喂进了 CDN 缓存**。教训——**发布前后别去请求那个"裸路径"，要带随机参数**。
  （排查手法与话术已写进 `headless-web-page-verify` 技能。）

### 2026-09-27 14:05 — 顶部加「实时天气」（按访问者 IP 猜城市）

  本人跑到哪它就跟着变。天气胶囊整块**居中**，和时间胶囊上下排、风格一致，四套皮肤都跟随。
- 改法：只动 `index.html` 三个地方，没碰 `data.js`

  3. 脚本区在时间脚本之后加一段 `initWeather()` 自执行函数。
- **接口选型（这块踩了坑，值得留档）**：网页有两条硬规矩，一开始选的接口全都撞上——
  - 站点是 **https**，就不能再调 **http** 接口，浏览器直接拦。所以 `ip-api`（只有 http）用不了；
  - 跨域必须被允许（`Access-Control-Allow-Origin`）。**太平洋电脑网**那个虽然返回中文省市名、

    | 步骤 | 接口 | 作用 |
    |---|---|---|
    | ① 定位 | `ipwho.is` | 拿访客经纬度（备用：`ipapi.co`） |
    | ② 译名 | `api.bigdatacloud.net/data/reverse-geocode-client?...localityLanguage=zh` | 经纬度 → 中文城市名 |
    | ③ 天气 | `api.open-meteo.com/v1/forecast` | 经纬度 → 实时天气（WMO 代码） |
- **加固（实测暴露的问题，都已修）**：
  - ⚠️ `ipwho.is` 偶发返回 `success:true` 但**没有经纬度**的空壳（实测撞到过一次，
    命令行却正常）⇒ 不能只看 `success`，必须**校验到 `latitude/longitude` 本身是不是有限数字**，
    不合格就抛错走备用接口；
  - 失败后加**重试**：最多 3 次、每次隔 4 秒。免费接口抖一下就永久空白，是不可接受的；
  - 城市名要**削后缀 + 繁转简**：接口对「济南」返回的是繁体「濟南市」，「北京」返回「北京市」

  - 缓存键带版本号（`wxCacheV1 → wxCacheV2`）：**数据结构一改就升版本号**，
    否则老访客浏览器里残留的旧格式缓存会被当成新数据用（这次就是这么翻车的：页面一直空白，
    但接口全通——因为读到了上一版遗留的旧缓存）；判定也加严到"有数据且 `temp` 是数字"才敢用；
  - 天气**不纳入**滚动入场动画（`revealOnScroll`）：它是异步来的，早挂 `.reveal` 会让它

### 2026-09-19 14:52 — 真正关掉手机浏览器的「自动反色」（找到官方写法了）

- 背景：上一版（11:11）加的三处加固发布后，和田的小米 15 上**依然**闪屏、浅色皮肤依然被深色盖住，而且在浏览器里**找不到**"网页深色适配"这个开关，没法确认是不是它在捣乱。
- 关键纠错：上一版把 `color-scheme` 写成 `light dark`，想表达"深浅我都能处理，你别插手"——**方向是反的**。查了 Chrome 官方文档《自动深色主题》（Auto Dark Theme）：浏览器**只认 `only` 这个关键字**才算"明确谢绝"。

### 2026-09-19 13:18 — 页脚加「最近更新」时间戳（用来自查缓存）

- 起因：普通访客（包括我们）分不清"网站没更新"和"自己拿到的是缓存里的旧副本"，来回排查很费劲。
- 做法：页脚加一行 `#buildTag`，由脚本读取 `document.lastModified`（浏览器从响应头拿到的"这个文件的最后修改时间"）自动填成「最近更新 YYYY-MM-DD HH:MM」。**不用手写日期，也不会忘记更新**；读不到时保持「—」，不编假日期。
- 用法：打开页面先看页脚那行时间。时间旧 = 拿到的是老副本（缓存问题）；时间新 = 服务器上就是这版。
- 样式：`.build-tag` 比页脚正文再淡一档（opacity .72），像一枚不抢眼的小印记。
- 13:24 已发布；**13:45:49 线上根地址才刷成新版，这次发布到可见等了约 21 分钟**（上午那次是十几分钟）。
- 【重要结论 · 以后照这个来】托管侧**只缓存 `.html` 这一种文件**，其它扩展名（`data.js` / `theme.css` / `README.md` / `og-image.js`）全是直通、发布即生效；而且 `/` 和 `/index.html` 是**两份独立的缓存，各自过期、时间还不同步**（这次 `/` 先刷新，`/index.html` 反而落后）。
  所以最省事的做法是：**让每次改动都别落在 `index.html` 上** —— 文案改 `data.js`（带 `?v=N`）、颜色改 `theme.css`（带 `?v=N`）、逻辑尽量挪进独立的 `.js`；`index.html` 越稳定越好，只在真改结构时才动它。这样发布就立刻生效，不用再等缓存过期。
